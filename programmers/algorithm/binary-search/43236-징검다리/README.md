# 징검다리

- 플랫폼: 프로그래머스
- 난이도: Level 4
- 분류: 이분 탐색 / Parametric Search, 그리디
- 언어: Python
- 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/43236

## 문제 핵심

바위 `n`개를 제거해서, **남은 바위와 출발점·도착점 사이 간격 중 가장 좁은 간격을 최대한 넓게** 만드는 문제다.

즉, "최솟값들 중 최댓값"을 구하는 유형이므로 **정답 자체를 이분 탐색**한다.

## 풀이 전략 3단계

### 1. 이분 탐색 대상 정하기

직접 답인 최소 간격을 구하기 어려우므로, **간격이 `m` 이상이 될 수 있는가?**를 판정하는 문제로 바꾼다.

- `l = 1`, `r = distance`: 답이 될 수 있는 간격의 범위
- `m = (l + r) // 2`: 최소 간격 후보

### 2. 판정 함수 만들기: 그리디로 한 번 순회하기

출발점부터 바위를 순서대로 확인한다.

- 직전에 남긴 위치(`cur`)와 현재 바위의 거리가 `m`보다 작으면 현재 바위를 제거한다.
- 거리가 `m` 이상이면 현재 바위를 남기고, 이 위치를 새로운 기준점으로 사용한다.

이 방식으로 한 번만 순회해도 `m` 이상의 간격을 만들기 위한 최소 제거 개수를 구할 수 있다. 현재 바위와의 간격이 이미 `m`보다 작다면, 현재 바위를 남길 방법은 없기 때문이다.

도착점도 바위처럼 판단해야 하므로 `rocks`에 `distance`를 추가한다.

### 3. 단조성으로 탐색 범위 좁히기

제거한 바위 수를 `n`과 비교한다.

- `removed_cnt > n`: `m`이 너무 크므로 실패 → `r = m - 1`
- `removed_cnt <= n`: `m`이 가능하므로 성공 → `answer = m`, `l = m + 1`

최소 간격 후보가 커질수록 제거해야 하는 바위 수는 같거나 증가한다. 따라서 가능 여부가 단조롭게 변하므로 이분 탐색을 적용할 수 있다.

성공하거나 실패한 `m`은 다음 범위에서 제외해야 탐색 범위가 줄어들고 무한 반복을 방지할 수 있다.

## 시간 복잡도

바위 수를 `k`, 전체 거리를 `distance`라고 하면 정렬에 `O(k log k)`, 이분 탐색과 각 순회에 `O(k log distance)`가 걸린다.
